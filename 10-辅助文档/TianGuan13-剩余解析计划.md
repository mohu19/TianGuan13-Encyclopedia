# 三、执行方法论

## 3.1 标准流程（沿用既往 70 篇成功经验）

```
1. 摸底       → 统计行数/文件/子目录分布，建 todo
2. 派子代理   → 3-4 个并行（按子类拆分），每代理带明确输出模板
3. 主代理深挖 → 亲自读基类/核心机制（不干等子代理）
4. 整合撰写   → 中文百科 + 锚点目录 + 精确数值表
5. 查漏核查   → 关键词双向核对（中英名）防命名误报
6. 收尾       → 代码索引附录 + skill 登记
```

## 3.2 质量守则

- **数值全部精确到源码**（血/伤/冷却/概率），禁止推测
- **中英双名核对**（40 个"缺失"教训：多为英文名 vs 中文名差异）
- **NOVA EDIT 单独标注**（每篇列 NOVA 修改清单）
- **"全了"声明前自我质疑**（用户多次验证：13K 断言被证伪）
- **文档末尾代码路径索引**（文件级行数表）

## 3.3 子代理拆分原则

| 行数 | 子代理数 | 拆分依据 |
|---|---|---|
| <15K | 1 | 整体解析 |
| 15-35K | 2 | 按子类 |
| 35-60K | 3 | 按子类+核心 |
| >60K | 4+ | 按子类+基类单独 |
